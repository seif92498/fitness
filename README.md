# فورمة

فورمة متابع أكل وتمرين ولياقة بالمصري. نسخة النشر الثابتة هي **`public/downloads/index.html`**: ملف HTML واحد فيه CSS وJavaScript والخط والصورة والقوائم. مفيش Framework ولا خطوات بناء مطلوبة لفتح الملف نفسه. الواجهة Responsive وRTL؛ التسجيل شغّال محليًا، حتى بدون إنترنت لو فتحت الملف مباشرة أو الصفحة مفتوحة بالفعل.

## شغّل وشارك

1. من المعاينة اختار **شارك التطبيق ← انسخ اللينك**. استخدم رابط منشور وصالح لصحابك، مش رابط `localhost` أو معاينة محتاجة تسجيل دخول. ممكن كمان تختار **نزّل ملف HTML**.
2. على الكمبيوتر افتح `public/index.html` مباشرة بمتصفح حديث. على الموبايل، افتح لينك الاستضافة من Safari أو Chrome؛ معاينة مرفق HTML في تطبيق دردشة أو مدير الملفات ممكن تمنع JavaScript أو التخزين، خصوصًا على iOS.
3. **[Netlify Drop](https://app.netlify.com/drop):** حُط `index.html` لوحده في فولدر وارفع الفولدر. **[GitHub Pages](https://pages.github.com/):** حط `index.html` في جذر الريبو، ثم `Settings → Pages → Deploy from a branch` واختر `main / (root)`. ابعت اللينك الناتج. مفيش إعداد بناء مطلوب للاستضافة الثابتة.
4. لو عايز ترفع الكود القابل للتعديل، نزّل **حزمة كود GitHub Pages** من قائمة المشاركة. فك الحزمة وارفع محتوياتها، مش ملف ZIP نفسه. ما ترفعش `.env` أو نسخ سجلك. لإعادة إنتاج الحزمة من المشروع شغّل `node scripts/build-fitness.mjs` ثم `python3 scripts/pack-github-pages.py`.

اللّينك العادي عمره ما بيحمل اسمك أو أي سجل. كل متصفح له بياناته. تقدر تنقل بياناتك بين الأجهزة بنسخة JSON من «حسابي»، وتصدّر سجلات الأكل والتمرين CSV. تحدّي الصحاب شغّال بتبادل رموز يدويًا، فيها اسم مستعار وأيام الاستمرار والتاريخ، مش السجل.

## الهيكل وقاعدة البيانات

- **التطبيق:** JavaScript وHTML وCSS بدون مكتبات. ملفات التأليف في `fitness-source/`؛ `scripts/build-fitness.mjs` يجمعهم مع الأصول المحلية ويحدّث `public/index.html`. الملف الناتج هو المطلوب للنشر، مش السكربت.
- **التخزين:** وثيقة JSON بإصدار `1` تحت مفتاح `forma.eg.v1` في `localStorage`. `try/catch` يخلّي التطبيق شغّال في الذاكرة لو المتصفح منع التخزين. ما فيش قاعدة بيانات علشان تخزن سجلاتك على السيرفر.
- **الاستضافة الكاملة:** Next.js بيقدّم نفس الملف على `/` و`/index.html`. `POST /api/ai` يمرّر الطلبات الاختيارية بعد الموافقة فقط، وما بيسجّلش محتواها في التطبيق. مسار `/api/health` بيختبر اتصال PostgreSQL/Drizzle للقالب، من غير جداول أو بيانات مستخدمين.

| المجموعة | المفتاح والعلاقة |
| --- | --- |
| `profile`, `settings` | بروفايل محلي واحد، هدف وحركة ووزن وإعدادات |
| `days` | مفتاح تاريخ `YYYY-MM-DD`. سجل الماية والنوم والمشي والكارديو والكافيين والمكمّلات والمفكّرة. `days[date].food` بيربط ID الأكل والوجبة بلقطة أرقام وقت الحفظ |
| `customFoods`, `savedMeals` | أكلات إضافية لكل 100 جم، ووجبات محفوظة بإدخالات قابلة للنسخ |
| `logs`, `customExercises`, `notes` | التسجيلات مرتبطة بمعرّف التمرين الفعلي، بما فيه البديل. الملاحظات مرتبطة بنفس المعرّف |
| `routineEdits`, `swaps`, `planChoices` | تمارين مخصصة باليوم والنظام، بدائل بالتمرين واليوم، واختيارات وجبات باليوم والوجبة |
| `measurements`, `reviews`, `photos` | تاريخ القياس والمراجعة والصورة المحلية. أحدث قياس وزن بيحدّث البروفايل |
| `friends` | صفوف تحدّي متبادلة اختياريًا يدويًا؛ ما فيهاش سجلات الصحة |

## تعديل وتشغيل نسخة السيرفر

- فتح نسخة الملف مباشرة مش محتاج Node أو PostgreSQL. لو عدّلت أي ملف في `fitness-source/`، شغّل `node scripts/build-fitness.mjs` علشان تعيد تجميع الملف.
- لتشغيل السيرفر خليك على نسخة Node المدعومة من Next.js، وثبّت الاعتمادات بـ `npm install` وبعدها `npm run dev`. افتح `http://localhost:3000`. لفحص البناء استخدم `npx next typegen` ثم `npm exec tsc -- --noEmit --pretty false` ثم `npm run build`.
- للذكاء الاصطناعي حط على السيرفر `ANTHROPIC_API_KEY` أو `OPENAI_API_KEY`. ممكن تحدد `ANTHROPIC_MODEL` / `OPENAI_MODEL` و`AI_PROVIDER=openai` لو الاتنين موجودين. خلي المفاتيح خاصة (من غير `NEXT_PUBLIC_`). لو هتنشر التحليل للعامة، اضبط حدود الصرف عند المزوّد وحماية الوصول على مستوى الاستضافة؛ الحد الحالي في الذاكرة لكل نسخة سيرفر، مش نظام حسابات. سياسات المزوّد بتطبق على البيانات اللي المستخدم قَبِل يبعتها.
- النسخة الثابتة من GitHub Pages / Netlify Drop مش بتشغّل مسار التحليل، ومش محتاجة المفتاح. كل الأدوات المحلية والمراجعة الأسبوعية شغّالة من غيره. تقدير الصورة يتراجع ويتعدّل قبل التسجيل؛ مفيش صورة وجبة بتتبعت من غير موافقة.

## اختبر بنفسك

اعمل بروفايل بالغ؛ سجّل جرامات أكلة وساعات نوم وماية؛ افتح «التمرين» وبدّل تمرين وسجّل وزن؛ افتح «تقدّمي» وأضف قياس وزن وشوف الهدف يتغير. حدّث الصفحة وتأكد إن البيانات موجودة، وجرّب نسخة JSON صحيحة وغير صحيحة. افتح الملف مرة من غير نت وجرب نفس الوظائف. لو هتجرب التحليل، افحص إنه مقفول من غير الموافقة وإنه بيعرض خطأ واضح من غير مفتاح. `scripts/smoke-fitness.cjs` يشغّل السيناريو تلقائيًا لو Playwright وChromium متاحين (ممكن تحدد مسار المكتبة في `PLAYWRIGHT_MODULE`).

## افتراضات وحدود

- السعرات والماكروز للمكونات والأكلات المصرية تقريبية وتختلف من وصفة للتانية. الطبخ وحرق التمرين وتقدير الصور أرقام إرشادية، مش تشخيص أو خطة علاج. دليل الحساسية مش مصدر معتمد للمكونات المشتركة أو التلوث العرضي. بروفايل الاحتياجات للبالغين.
- المسافة والنوم والأوزان بتتسجّل يدويًا. مفيش ربط تلقائي بحساسات التليفون أو Health app. الإملاء الصوتي المدمج يحتاج متصفح يدعم التعرّف العربي على الجهاز؛ الكتابة اليدوية متاحة دائمًا.
- الصفحة المفتوحة أو الملف المحلي يشتغلوا من غير اتصال. النسخة الواحدة مش بتثبّت Service Worker وما بتنبهش في الخلفية ولا تضمن إعادة تحميل اللينك بدون إنترنت. مفيش حسابات أو مزامنة سحابية. المقارنات الأسبوعية وتقدير توقيت الهدف مش ضمان لنتيجة أو وصفة لعلاج إصابة.
- خطوات تالية مقترحة: وضع رمضان، مقارنة صور محلية جنب بعض بتفاصيل أكتر، واجهة إنجليزي، تثبيت PWA مع إتاحة إعادة الفتح وهو أوفلاين، ومزامنة مشفّرة اختيارية بموافقة منفصلة.
